# Domain & HTTPS Deployment Readiness

**Date:** August 28, 2026

## 1. Network Topology
To migrate this architecture from the local Docker Compose configuration to a real production environment, the following topology is required:

### Frontend
- **URL**: `https://learning.mospi.gov.in`
- **Component**: Nginx serving static assets generated by Vite.
- **Allowed Origin Config**: Needs to point to the production API URL.

### Backend API
- **URL**: `https://api.learning.mospi.gov.in`
- **Component**: Node.js / Express process running on port 4000.
- **Allowed Origin Config**: `CORS_ORIGIN` must be exactly `https://learning.mospi.gov.in`.

## 2. TLS Termination & Reverse Proxy
- The Node.js application is intentionally NOT configured to handle raw HTTPS certificates.
- TLS termination must occur at a Reverse Proxy (e.g., AWS ALB, Cloudflare, Nginx, or Traefik) positioned in front of the application.
- The proxy must forward requests to the Docker container over port 80 (Frontend) and 4000 (API).

## 3. Secure Cookies & Headers
- If transitioning to Cookie-based JWT auth in the future, `Secure; HttpOnly; SameSite=Strict` flags will mandate HTTPS.
- Currently, JWTs are handled via `Authorization: Bearer` headers which inherently require HTTPS to prevent token sniffing in transit.

## 4. Pending External Dependencies
- **DNS Records**: A/CNAME records for `learning.mospi.gov.in` and `api.learning.mospi.gov.in`.
- **SSL Certificates**: CA-signed certificates for both domains.
- **Cloud Load Balancer**: Provisioned and configured to terminate TLS and map ports.
